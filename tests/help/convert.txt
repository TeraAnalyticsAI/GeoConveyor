Convert a dataset to another format, optionally reprojecting it. Point clouds convert to LAS, LAZ, COPC or vector point layers

Usage: terrio convert [OPTIONS] <INPUT> <OUTPUT>

Arguments:
  <INPUT>   The input dataset
  <OUTPUT>  The output path

Options:
  -f, --format <FORMAT>
          The output format's short name (`GTiff`, `COG`, `GPKG`, `ESRI Shapefile`...). By default, chosen from the output's extension. Builds with the GDAL backend also write with any GDAL driver: rasters (`NITF`, `KEA`, `GRIB`...) and vector layers (`DXF`, `OpenFileGDB`, `MapInfo File`, `SQLite`...), and choose GDAL's driver for extensions terrio has none for
  -l, --layer <LAYERS>
          Only these layers of a vector dataset
      --driver <DRIVER>
          Open the input with this driver: `gdal` uses the GDAL backend (builds with the `gdal` feature), as a `GDAL:` prefix on the path does
      --t-srs <CRS>
          Reproject into this CRS
      --compress <COMPRESS>
          Compression: GeoTIFF/COG NONE, LZW, DEFLATE, ZSTD, PACKBITS, JPEG, WEBP; Zarr NONE, ZLIB (v2), GZIP, ZSTD; GeoPackage tiles PNG, JPEG
      --tile-size <TILE_SIZE>
          GeoTIFF/COG tile size
      --bigtiff
          Write BigTIFF
      --srcwin <XOFF> <YOFF> <XSIZE> <YSIZE>
          Convert only this window of a raster: first column, first row, width and height (in the overview's pixels with --overview). GeoTIFFs, local or remote, are read in place
      --overview <N>
          Convert a raster's overview N (0 is the largest) instead of its full resolution
      --oo <KEY=VALUE>
          An open option, as GDAL names it: `KEY=VALUE` (CSV: X_POSSIBLE_NAMES, Y_POSSIBLE_NAMES, GEOM_POSSIBLE_NAMES, AUTODETECT_TYPE, KEEP_GEOM_COLUMNS, SEPARATOR; PMTiles, MBTiles and MVT: ZOOM_LEVEL, CLIP)
      --lco <KEY=VALUE>
          A vector layer creation option, as GDAL names it: `KEY=VALUE` (CSV: GEOMETRY=AS_WKT|AS_XY; GeoJSON: RFC7946=YES; vector tiles: MINZOOM, MAXZOOM, EXTENT, BUFFER, SIMPLIFICATION, SIMPLIFICATION_MAX_ZOOM, NAME, DESCRIPTION, TYPE)
      --dsco <KEY=VALUE>
          A dataset creation option of a GDAL vector driver (`ogr2ogr -dsco`): `KEY=VALUE`. Builds with the GDAL backend only; GDAL drivers also take `--lco` as GDAL defines it
      --co <KEY=VALUE>
          A raster creation option, as GDAL names it: `KEY=VALUE` (Zarr: FORMAT=ZARR_V2|ZARR_V3; netCDF: FORMAT=NC|NC2|NC5; PMTiles and MBTiles: TILE_FORMAT, RESAMPLING, ZOOM_LEVEL_STRATEGY, MINZOOM, MAXZOOM, QUALITY, NAME, DESCRIPTION, TYPE)
      --minzoom <MINZOOM>
          Tile archives (PMTiles, MBTiles, MVT): the lowest zoom level written
      --maxzoom <MAXZOOM>
          Tile archives (PMTiles, MBTiles, MVT): the highest zoom level written
  -h, --help
          Print help

Vector options:
      --where <EXPR>
          Keep the features matching this OGR SQL expression, such as "pop > 1e6 AND name LIKE 'A%'"
      --spat <XMIN> <YMIN> <XMAX> <YMAX>
          Keep the features intersecting this rectangle
      --spat-srs <CRS>
          The CRS of the --spat rectangle. By default, that of the layer
      --select <FIELDS>
          Keep only these fields, in this order (comma-separated)
      --limit <N>
          Keep at most this many features per layer
      --sql <STATEMENT>
          Read the result of "SELECT fields FROM layer [WHERE ...] [ORDER BY field [DESC]] [LIMIT n]"
      --nln <NAME>
          The output layer name
      --nlt <TYPE>
          Convert geometries: PROMOTE_TO_MULTI, POINT, LINESTRING, POLYGON, MULTIPOINT, MULTILINESTRING, MULTIPOLYGON, GEOMETRYCOLLECTION, GEOMETRY or CONVERT_TO_LINEAR
      --explodecollections
          Write each part of multi-part geometries as its own feature
      --s-srs <CRS>
          The CRS of the input, overriding what it declares
      --a-srs <CRS>
          Assign this CRS to the output, without reprojecting
      --append
          Add the features to the layers of an existing output (a GeoPackage, or the tiles of a PMTiles or MBTiles archive); for a raster, add it to an existing archive of image tiles
      --overwrite
          Replace the layers of the same name in an existing output (other GeoPackage layers stay)

Point cloud options:
      --bounds <XMIN> <YMIN> <XMAX> <YMAX>
          Keep the points in these bounds, in the input's CRS
      --z-range <MIN> <MAX>
          Keep the points with z in this range
      --class <CLASSES>
          Keep the points of these classifications (comma-separated, such as 2,6)
      --returns <RETURNS>
          Keep these returns of each pulse (comma-separated): first, last, intermediate, only
      --max-level <LEVEL>
          COPC and EPT: read down to this octree level (0 is the root)
      --resolution <SPACING>
          COPC and EPT: read the octree levels needed for this point spacing
      --max-points <N>
          Read at most about this many points: COPC and EPT down to the deepest level that fits, others by keeping every n-th point
      --point-format <N>
          The output point data record format (0 to 10). By default, the input's (6 to 8 for COPC)
      --las-version <1.N>
          The output LAS version, such as 1.2 or 1.4. By default, the input's, raised as the point format needs
      --scale <X> <Y> <Z>
          The scale of the stored X, Y and Z
      --offset <X> <Y> <Z>
          The offset of the stored X, Y and Z
      --dims <DIMS>
          For vector, PLY and E57 outputs, the dimensions written (comma-separated). All by default
      --ply-encoding <ENCODING>
          PLY outputs: ascii (the default, as PDAL's), binary_little_endian or binary_big_endian
      --ply-precision <DIGITS>
          PLY ASCII outputs: the digits after the decimal point of floats (by default, as many as needed to read the same values back)
      --ept-data-type <TYPE>
          EPT outputs: how the nodes' points are stored: laszip (the default, as Entwine), binary or zstandard
      --chunk-points <N>
          The points read and written at a time: point clouds are converted in chunks, in bounded memory, whatever their size (about a million points by default) [default: 0]
